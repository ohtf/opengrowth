# Conformance corpus

Behaviour shared between opengrowth and the upstream Python engine, defined as data. See `spec/standard.md` section 8.

There are two kinds of oracle, with different authority:

- **`independent/`**: vectors computed by implementations that share no code with `rcpchgrowth`. These are the clinical-accuracy gate. They are imported as published and never regenerated by this project.
- **`expected/`**: goldens captured from the pinned Python reference implementation by `s/goldens`. Never hand-edited. A golden change needs a stated rationale in the commit.

If an independent vector and a Python golden disagree beyond tolerance, that is a finding about the Python engine. Record it as a defect for classification (`spec/standard.md` section 6); don't make Rust match whichever is convenient.

## Goldens

All are produced by `s/goldens` from `rcpchgrowth==4.6.5` installed from PyPI by `s/reference-python`, or, for `http_*`, by `s/reference-server`, which checks out the upstream server at a pinned commit and installs its pinned dependencies with `rcpchgrowth` 4.6.5 (4.6.4, which the server pins, differs only in `_build_info.py`). Each file records its generator and the exact Python, SciPy, NumPy, and `rcpchgrowth` versions.

| File | Generator | Contents |
| --- | --- | --- |
| `uk-who-r-vector-inputs.json` | `uk_who_r_vectors.py` | Python `Measurement` output for every R-vector input: ages, SDS, centiles, and error strings. |
| `normal-grid.json` | `normal_grid.py` | `scipy.stats.norm.cdf` over z in [-40, 40] and `norm.ppf` over p from 1e-307 to 1 - 1e-15. |
| `python-round.json` | `python_round.py` | CPython `round(x, n)` for ties, near-ties, and a seeded random sample. |
| `numpy-round.json` | `numpy_round.py` | Python `round(x, n)` on a NumPy `float64`, which uses NumPy's algorithm, and `round(x)` with no digits. Weighted to five-decimal values, where NumPy and CPython disagree most. |
| `python-repr.json` | `python_repr.py` | CPython `repr(float)` for random bit patterns, decade boundaries, and API-like values. |
| `http-uk-who.json` | `http_uk_who.py` | Responses from `digital-growth-charts-server` at 29bb4e9 (FastAPI 0.116.1, Pydantic 2.11.7), captured with Starlette's `TestClient`: status, recorded headers, and SHA-256 of the body and of the body with provenance removed. Full bodies for the hand-written cases; digests only for the R-vector corpus and the age and gestation grid. Needs `s/reference-server`. |
| `http-uk-who-charts.json` | `http_uk_who_charts.py` | `POST /uk-who/chart-coordinates` from the same server, with its named-format chart files regenerated by rcpchgrowth 4.6.5 in a temporary copy, because the committed files are stale (`spec/standard.md` section 6.3). Records, for each named format, the digest the unmodified server returns too. |

Goldens contain calculated outputs, never LMS tables.

## Results at this commit

Measured on Linux x86_64 against rcpchgrowth 4.6.5, SciPy 1.18.1, NumPy 2.5.5, CPython 3.13.7:

| Comparison | Result |
| --- | --- |
| UK-WHO SDS vs R vectors | All 7,721 computed SDS within 1e-3 (max 9.65e-4); all 247 absent values absent in both |
| UK-WHO SDS vs Python | 7,721 of 7,721 **bit-identical** |
| Decimal ages vs Python | 7,968 of 7,968 bit-identical |
| Error strings vs Python | All match |
| UK-WHO centiles vs Python | 7,721 of 7,721 **bit-identical**, unrounded |
| `python_round` vs CPython | 10,045 of 10,045 bit-identical |
| `numpy_round` vs NumPy | 9,844 of 9,844 bit-identical; CPython rounding would differ in 37 |
| Normal CDF (SciPy `ndtr`, translated) vs SciPy | 11,969 of 11,969 bit-identical, z from -40 to 40 |
| Normal PPF (SciPy `ndtri`, translated) vs SciPy | 4,330 of 4,330 bit-identical, p from 1e-307 |
| `python_repr` vs CPython | 10,484 of 10,484 identical |
| UK-WHO HTTP responses vs FastAPI | 5,284 of 5,286 byte-identical outside provenance; the other 2 are enumerated Category 3 fixes (upstream 500, opengrowth 422) |
| UK-WHO chart coordinates vs FastAPI | 60 of 60 byte-identical outside provenance, with the named-format files regenerated; all 32 named-format responses differ from the server's stale stored files |

Bit-identity on Linux depends on using the platform `pow`, `exp`, and `log` (glibc), as CPython and SciPy do. The portable `libm` crate's `pow` is 98% bit-exact for SDS. Other platforms are not yet measured (`R34`).

## Running

```sh
s/reference-python   # once: create the pinned Python environment
s/goldens            # only when regenerating goldens
s/conformance        # run the suites with their reports
```

`cargo test` runs every suite, in CI too, against the embedded tables; set `$OPENGROWTH_REFERENCE_DATA_DIR` to layer imported files over them. `s/conformance` runs the same suites with their agreement reports.
