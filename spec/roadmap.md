# Roadmap

Legend: `[x]` done, `[~]` in progress, `[ ]` not started

Every actionable item has a stable `R<number>` code. Codes are never renumbered and never reused. Standing constraints are plain bullets and carry no checkbox.

## Standing constraints

- The independent R and WHO `anthro` vectors are the clinical-accuracy gate. The Python engine is the reference implementation for everything they do not cover. Goldens are captured from it, never hand-edited.
- opengrowth is an OHTF project, not an RCPCH project. Upstream attribution is preserved; RCPCH branding is not used.
- UK90 tables are in the repository for pre-alpha research only; nothing is used for patient care until UKRI grants a licence (`Q1`).
- No reference table ships without recorded provenance, licence, and integrity tests.
- No phase is complete while its differential tests are red.
- Preterm and early-infant behaviour is the highest-risk area throughout and gets clinical review, not just passing tests.

- [~] **R9 - Implement reference selection.** *UK-WHO selection was done first, out of the planned order, because it was the feasibility slice the R vectors could test. - [~] **R10 - Implement SDS and measurement conversion.** *UK-WHO SDS done, bit-identical to Python on the corpus. - [~] **R11 - Implement centile bands and clinical comment strings.** *Done for the UK-WHO paths, byte-identical in every captured response. CDC formats exist but are untested until CDC is ported.* Exact string reproduction, including the "on or near" band width and the measurement-method renaming.

- [x] **R31 - Write a Python-compatible float serialiser.** *`opengrowth_core::pyfmt`, identical to CPython `repr` on 10,484 values including round-half-even ties.* Emits floats exactly as CPython `repr` does (`115.0`, `1e-05`, the exponent thresholds), tested against a CPython golden, for byte-identical responses. - [x] **R32 - Try a bit-exact port of SciPy's `ndtr` and `ndtri`.** *Done and adopted, 2026-11-18: 100% bit-exact on the SciPy grid on Linux, where the CDF was 54% and the PPF 31%; licence reviewed (`Q5`, `NOTICE.md`).* Cephes via SciPy's `xsf` (BSD-3-Clause, after licence review), measured with the existing SciPy-grid test. - [ ] **R38 - WebAssembly build for in-browser calculation.** An `opengrowth-wasm` crate (`wasm-bindgen`) exposing `measure` and chart coordinates, published as an npm package, so the chart component can calculate on the device and **no patient data leaves the browser**.   - **Reference data in the browser.** Either embedded in the package, which is onward redistribution to every user and waits on `Q1`, or fetched at run time from the deploying organisation's own origin and verified against the same checksum manifest, which works under either outcome of `Q1`.

  - **Provenance unchanged:** results still name the engine version and the checksum of each table read, so a chart can show what calculated it.
  - **Clinical safety:** a hazard log entry for calculating on uncontrolled client devices (stale cached bundles, tampered pages), with mitigations such as subresource integrity and a version check against the server.
  - A demonstration in the React repository (`R28`).
- [ ] **R39 - Privacy and data-protection statement.** For anyone deploying opengrowth or the hosted API: what personal data a request contains (date of birth, sex, measurements, dates), that the server and engine store nothing and log no request bodies, a data-flow diagram for each surface (CLI, server, MCP, WASM), and material that makes a deployer's DPIA and DTAC submission quick.
